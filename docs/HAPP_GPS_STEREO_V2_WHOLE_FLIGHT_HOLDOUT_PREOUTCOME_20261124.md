# Happ V2 frozen geographic calibration leave-flight-out test (2026-11-24)

**Before numerical original drone-GPS stereo flight reproduction.** Open public author source already described in v1 source-only contract `HAPP_PUBLIC_GEOREGISTERED_3D_CAMERA_SOURCE_V1_PREOUTCOME_20261124.md`, tag `v1.0.1`, commit `34d2f56bcee1eab9207890938aedd90a079bfcde`. The original 2024 paper already reports geographical thermal tracking and median 1.8m error, so a successful reproduction here **must not be described as new ecological evidence**. The aim is to prove an end-to-end, measurement-calibrated, geographic 3D camera reconstruction with an **independent heldout drone flight**, addressing the engineering limitation of Münster local-only tracks.

Convert original drone GPS WGS84 latlon to **EPSG:32632 UTM metre XY**, then subtract the UTM position of original reference `ref` for numerically stable local **world XY**. ## Fixed reconstruction algorithm and numerical scoring

1. With original source rows, parse only original source specified numeric fields, no other `ForStatisticalAnalysis` bat activities or bat video images. Complete `x1,y1,x2,y2,lat,lon,height` with finite values forms one matched stereo+drone **calibration/validation row**. Original source missing coordinate or exposure values are source-record not localized and **excluded solely by finite-value support**, not based on their error magnitude or favorable outcome. Record original source row totals and finite matched-row totals. Require >=20 finite matched rows in each complete flight, else **SOURCE_SUPPORT_STOP**. Count support rows and reject duplicates of source `nr` within each flight to avoid repeated measurements masquerading as independent events. No invented zeros or interpolation.
2. Camera intrinsics from source original `camintrinsicMatrix1/2` and `distortion1/2` without post-outcome changes; calibrate both cameras separately by `cv2.solvePnP(..., flags=cv2.SOLVEPNP_SQPNP)` using **all finite rows of the TRAIN flight only** and source GPS-derived world XYZ. Use no cross-fitting, adaptive outlier dropping, RANSAC threshold tuning or manual orientation change after seeing heldout scores. If any PnP fails or returns nonfinite R/t, **hard STOP** for both directions, not rescue via another PnP method.
3. Use the two trained projection matrices `K_i [R_i | t_i]` and `cv2.triangulatePoints` on matched heldout flight's **only pixel coordinates**. Convert homogeneous to XYZ, require finite coordinates; count reconstruction invalids and report them as failures, **not** cherry-pick a favorable subset. For final error metrics, if *any source originally fully supported heldout row* reconstructs non-finite/infinite, **stop this arm** without deleting it.
4. Compare heldout reconstructed XYZ with original heldout drone GPS world XYZ (which were **not used for fitting**) using Euclidean 3D distance in same UTM-reference metre XY + source altitude Z. Report each flight: n total source rows, n finite matching pairs, median, mean, RMSE, 90th percentile error, mean XY error, mean Z error, original source camera baseline distance. Report both directions A→B and B→A, mean of 2 flight-level median errors as main summary and maximum of 2 medians. No pseudo-independent GPS-frame CI and **no p-value**.
5. Fixed engineering acceptance, not ecological hypothesis: both flight-level median heldout errors <= **3.0m** (based on author-reported typical 1.8m, not tuned from source heldout), both 90th-percentile errors <= **10m**, both arms cover >=20 matched rows, camera R matrices determinant ~+1 and no invalid heldout reconstruction. If any criterion fails, keep raw scores and mark `TECHNICAL_CALIBRATION_NOT_TRANSFERABLE_UNDER_LOCKED_METHOD`, not change the model/grid or drop the worse flight.
6. Independent known-truth tests before original source numeric opening: synthetic camera poses and projected 3D GPS points, exact triangulation under matched poses, explicit heldout world-coordinate non-leakage and source finite-missing-row discipline. **Source GPS source accuracy limits are not quantified by this test.**
7. Publication software code in the original open GitHub is prior art. The native method is OpenCV PnP and homogeneous triangulation, not a newly invented 3D SDM. A technical PASS under flight-heldout evidence is **not** co-registration with forest LiDAR; that requires real exact-world LiDAR tile and dates, source vegetation class/air mask, source detection kernel and bat events with known site/time.

## Fail-closed real bat reconstruction branch
The author GitHub has one actual bat flight image example at `Turbine2_Setup4_2022-06-23_21-41/images/bat_recording/`. **DO NOT** perform bat source reconstruction or report bat flight altitude/behavior under this v2 protocol. Those images, 2D source point matching, event identities and world-coordinate uncertainties need a **subsequent explicit separate freeze** after calibration performance is measured. A camera calibration pass does not prove downstream bat 3D measurement error or animal sample independence.

**Claim ceiling:** at most a reproduction of already-published absolute geographic thermal 3D tracking calibrated by GNSS, **within one wind turbine setup** and independent drone flight, not a novel bat ecological niche claim. `batter/main` and frozen JAE, ODSP N2 and esdm E5 remain untouched.
