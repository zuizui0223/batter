# Münster original CSV v2.2 — first-header labels, no coordinates (2026-11-24)

After source v2.1 [Actions #45206122875](https://github.com/zuizui0223/batter/actions/runs/45206122875), artifact 14833946603, the source grammar has now been diagnosed **without any original XYZ values being printed**: all 16 source track/lamppost CSVs begin with exactly one *textual* header row (no raw coordinate values there), but original bat8 versions have **6 columns**, while other original files have 3 columns. Thus frozen v2 exactly-three-numeric-columns parser correctly issued **SOURCE_FORMAT_STOP**; interpreting an arbitrary six-column table as two XYZ streams would be unjustified. Most original early rows have `NaN` localisations, which must not be treated as bat absence or low altitude. The first lexical diagnostic omitted first-row literal labels because they contain digits or other punctuation.

**V2.2 strictly technical source-only amendment**: recheck original SHA256 and first physical CSV row for all 16 files; print the **literal first-row header labels** (up to 6 source fields, <=80 characters) *only if each header field is nonnumeric*, and the source filename and column count. Do not parse or print any numeric coordinate rows, axis ranges, bat heights, distances, movement speed, species assignments, site association, or ecological effect. The 6-column meaning must be determined from the actual original headers before any source-numeric fix is allowed. Previous v2 STOP and v2.1 schema remain archived independently.

This is an observation metadata clarification, not method tuning or a way to find a positive bat habitat result. No source LiDAR tile/rigid-body transform has been authenticated, and Gate A/B/C for calibrated bat×LiDAR 3D SDM remain open.
