## Locked algorithm and reporting

1. Re-fetch author source exact commit and verify all five frozen author blobs (A drone, camera, three animal image-location files) before opening any original bat 2D numerical locations. In V3 do not open B drone GPS (the source camera setup has already been independently evaluated in V2). Use **the unchanged V2 source fit method**: pyproj WGS84→UTM EPSG:32632 XY relative to original author reference, original source GPS altitude unchanged, both camera OpenCV `SOLVEPNP_SQPNP` on all A original matched stereo-GPS source rows, no source leave-one-*bat*-out fitting because there is no bat ground truth.
2. From trained `P1/P2` camera matrices, derive the epipolar Fundamental matrix `F=K2^{-T}[T]×R K1^{-1}` from source camera projection extrinsics. Check rank-2 property, epipolar constraint in synthetic known-truth tests. Use original author `batflight3d.load_and_correspond_PTS`/original `detectCorrespondingPoints` for 2D candidate correspondence with EXACT author-published `areaRatio=4`, `maxDistFromEpiline=6`; use original precomputed 2D positions and original imagelist frame matches. DO NOT retune detector image score, area ratio or epipolar distance based on recovered 3D heights.
3. Compare unique original source `nr` frame keys and original 2D image candidates; preserve positive original source candidates as possibilities, no extra manually paired points; missing/nonfinite source x/y or nonpositive area candidates are **source-detection-unusable**, not bat biological absence, and excluded by fixed purely technical support rule. Record source candidate and excluded metadata counts. If original bat recording frames and camera candidate IDs do not overlap, or no stereo matches, **SOURCE_BAT_3D_RECONSTRUCTION_STOP** and do not relax correspondence criteria.
4. Reconstruct stereo bat source coordinates using `cv2.triangulatePoints` and known GPS-referenced (not measured AGL) camera projections; mark nonfinite world 3D as failed localisations rather than 0 or arbitrary beam direction. Report **number of 2D stereo candidate pairs**, **valid reconstructed 3D source coordinate points**, **number of distinct original image frames with valid matches**, number rejected for invalid source projection, and **median/p90 total two-camera reprojection residual in pixels**. No source raw bat XYZ is committed/published; no bat flight physical height/velocity/clutter distances or ecological spatial preferences are computed in V3.
5. This is a technical admission if >=1 valid 3D bat stereo point and >=1 original image frame with a match, and source camera/epipolar geometry tested. A candidate stereo reconstruction has **no independent GPS validation of bat-specific localization error**, no confirmed species ID and no automatic flying-bat 3D niche utilization likelihood. Sensor perspective errors, false 2D point detection, reflection and motion autocorrelation are not controlled.
6. The original study includes a known bat flight example for **one turbine site** in open wind farm, not multiple independent forest plots. Only a subsequent independently site-matched vegetation LiDAR surface with known air/occlusion and q permits a real clutter field test. The previous Münster 197 local points and current turbine world-GPS-referenced points must never be treated as the same spatial site.
